# 订单统计分析设计规格

- **日期**：2026-06-24
- **模块**：后端 `v7-shop-services` + 前端 `v7-shop-admin`
- **页面**：首页 → 统计分析
- **状态**：V1 需求已确认并冻结，待制定实施计划

## 1. 背景与目标

当前首页只有固定的今日、当月订单及销售额统计，不能由用户选择时间范围、员工或部门，也不能按天/月查看趋势。

V1 新增独立的“统计分析”菜单，为有权限的登录用户提供：

1. 按员工或部门统计订单。
2. 员工和部门均支持多选，多选结果同时提供汇总和分组数据。
3. 按自然日或自然月聚合。
4. 支持订单平台和历史下单域名筛选。
5. 支持多币种统一换算、个人长期汇率和本次查询临时汇率。
6. 提供汇总卡片、趋势图、聚合表格及异步 Excel 导出。
7. 严格沿用现有订单数据权限和网站上下文。

## 2. V1 范围

### 2.1 包含

- 新增“首页 → 统计分析”菜单，路由 `/statistics`。
- 所有已登录角色均可访问，无额外菜单权限；数据范围由后端控制。
- 时间范围选择。
- 按天、按月聚合。
- 按员工、按部门统计。
- 员工、部门、平台、域名多选。
- 汇总、趋势、分组分页、时间 × 分组明细。
- 个人报表配置：目标币种、IANA 时区、个人汇率。
- 查询时临时汇率。
- 统计结果快照、短期缓存、长查询异步化和取消。
- 聚合结果 Excel 导出。

### 2.2 不包含

- 商品数量。
- AI 积分消耗。
- PaymentStatus 筛选或按支付状态排除订单。
- 同比、环比。
- 平台分组或域名分组。
- 逐笔订单明细。
- 从统计页钻取或跳转订单管理。
- 查询条件 URL 分享。
- 服务端查询历史。
- 个人汇率历史版本。

## 3. 核心统计口径

统计数据只使用实体状态不是 `DELETED` 的订单。业务分类使用订单当前的 `OrderStatus`；每次查询反映查询生成时的当前状态。

### 3.1 订单指标

| 指标 | 公式 |
|---|---|
| 订单数 | 所有符合条件订单数 |
| 无效订单数 | `OrderStatus.INVALID` 订单数 |
| 有效订单数 | 订单数 − 无效订单数 |
| 签收订单数 | `OrderStatus.DELIVERED` 订单数 |
| 未签收订单数 | 有效订单数 − 签收订单数 |
| 签收率 | 签收订单数 ÷ 有效订单数 × 100% |

有效订单数为 0 时，签收率返回 `null`，前端显示 `--`，不显示 `0%`。

签收率显示保留两位小数并四舍五入；Excel 保存原始比例数值并使用百分比格式。

### 3.2 销售额指标

销售额统一使用 `Order.financialInfo.totalAmount`，不重新计算商品金额、运费、折扣或税费。

| 指标 | 订单范围 |
|---|---|
| 无效订单销售额 | `OrderStatus.INVALID` |
| 签收销售额 | `OrderStatus.DELIVERED` |
| 未签收订单销售额 | `OrderStatus` 既不是 `INVALID`，也不是 `DELIVERED` |
| 总销售额 | 上述三类销售额之和 |

所有成功换算的订单必须满足：

```text
总销售额 = 无效订单销售额 + 未签收订单销售额 + 签收销售额
```

实现时先按高精度十进制完成逐笔换算和分类汇总，再对分类汇总结果统一舍入；总销售额由三类销售额相加，避免页面和 Excel 出现尾数差异。

## 4. 统计维度

### 4.1 按员工

- 员工可多选。
- 只统计订单历史快照 `contextInfo.salesUid` 命中的订单。
- 按 `salesUid` 分组。
- 员工调岗不改变历史订单的员工归属。
- 同一员工被重复命中时只统计一次。
- 选择器普通状态优先展示当前可选人员；打开“包含历史员工”后，补充停用、隐藏、删除或只存在于历史订单中的销售归属人。
- 历史员工名称优先使用当前用户名称；当前记录不存在时使用订单快照 `salesPerson`，并标记为“历史”。

员工角色固定使用按员工模式，自动选中本人且不可修改，不展示按部门模式。

### 4.2 按部门

- 部门可多选。
- 只统计订单历史快照 `contextInfo.departmentId` 等于选中部门 ID 的订单。
- 按历史 `departmentId` 分组。
- 选择某部门本身不代表递归统计其子部门。
- 部门树交互复用订单管理现有规则：树组件使用 `check-strictly`，点击父节点时前端将其下级节点一并勾选；后端只处理最终明确提交的部门 ID。
- 同时选择父部门和子部门不会重复统计，因为一笔订单只有一个历史部门 ID。
- 打开“包含历史部门”后，可选择停用或已删除部门。
- 分组名称优先使用部门当前名称；当前记录不存在时使用订单快照 `department`，并标记为“历史”。

### 4.3 模式切换

- 页面提供“按员工 / 按部门”切换。
- 默认按员工。
- 两种模式分别保留各自当前会话中的选择。
- 查询请求只提交当前模式的数据。
- 员工和部门不允许在同一次查询中混合统计。

### 4.4 未归属

管理员和公司管理员可选择虚拟项“未归属”：

- 员工模式：`contextInfo.salesUid IS NULL`。
- 部门模式：`contextInfo.departmentId IS NULL`。

部门管理员、深度部门管理员、部门树用户及普通员工不可选择“未归属”。

## 5. 筛选条件

### 5.1 时间

- 使用订单 `orderTime`。
- 开始日期和结束日期均按用户时区的自然日解释。
- 开始边界包含，结束边界为结束日期次日 00:00 的排他边界。
- 如果结束日期是用户时区的今天，数据截止时间取查询生成时刻，不包含未来时间。
- 不允许选择未来日期。

默认值：

- 按天：最近 30 个自然日，包含今天。
- 按月：最近 12 个自然月，包含当前月。

限制：

- 按天最多 62 个自然日。
- 按月时间跨度不得超过 5 年。
- 按天超过限制时阻止查询并提示改用按月，不自动改变粒度。

按月允许任意日期范围。首月或末月不是完整自然月时，仍按实际选中范围统计，并在返回桶中标记 `partial=true`。

### 5.2 平台

平台为多选，值来自 `WebsiteTypeEnum`：

```text
V7_SHOP
SHOPLINE
XYZ
```

- 空选表示全部平台。
- 多选平台之间使用 OR。

### 5.3 域名

域名按订单历史快照 `contextInfo.websiteUrl` 精确匹配：

- 多选域名之间使用 OR。
- 空选表示全部域名。
- 平台条件与域名条件之间使用 AND。
- 忽略大小写。
- 输入时去除协议、端口、路径和末尾点后得到 Host。
- 不做 Punycode 转换。
- `www.example.com` 和 `example.com` 视为不同域名。

域名候选：

- 只按公司、登录用户订单数据权限和网站上下文过滤。
- 不随当前日期、平台、员工或部门筛选联动。
- 总后台可搜索当前权限范围内订单出现过的全部历史域名。
- 网站后台固定限制当前 `websiteId`，候选只来自该网站历史订单。

订单没有 `contextInfo` 或 `websiteUrl` 为空时：

- 未选择域名时正常参与统计。
- 选择域名时不匹配任何域名，不参与结果。

### 5.4 选择要求

- 管理员和各类管理账号必须至少选择一个员工、部门或允许的“未归属”项，避免误查全公司。
- 员工账号自动选择本人。
- 页面提供“全选当前权限范围”，但必须由用户主动点击。
- 员工选择支持按姓名、手机号和内部 ID 搜索。
- 部门选择支持按名称搜索并定位树节点。
- 手机号只用于搜索，不进入结果或导出。

## 6. 时间与时区

### 6.1 配置

- 保存 IANA 时区标识，例如 `Asia/Shanghai`、`America/Los_Angeles`。
- 不保存固定 UTC 偏移量。
- 由时区规则自动处理夏令时。
- 首次使用默认浏览器检测到的 IANA 时区，并保存到个人配置。

### 6.2 历史订单解释

当前数据库连接和后端日期序列化以 `Asia/Shanghai` 为基准，历史 `orderTime` 为无时区 `LocalDateTime`。

统计时统一按以下规则解释：

1. 将数据库 `orderTime` 视为 `Asia/Shanghai` 本地时间。
2. 将用户所选自然日/月边界从用户 IANA 时区转换为同一时刻。
3. 再转换为 `Asia/Shanghai` 的 `LocalDateTime` 作为数据库查询边界。

不得修改历史订单时间。

### 6.3 时间桶

后端必须在应用层按用户时区生成每个日/月桶的准确开始和结束时刻，再转换成数据库时间。不能依赖固定时差，因为夏令时可能使单日不是固定 24 小时。

返回结果必须补齐所选范围内所有自然日或自然月：

- 无订单桶的订单数和销售额返回 0。
- 无有效订单桶的签收率返回 `null`。
- 趋势图保持连续。

## 7. 数据权限

统计接口只要求登录，不允许前端决定数据范围。后端必须在应用任何用户筛选之前先计算订单访问范围。

### 7.1 基础角色

| 用户类型 | 可访问范围 |
|---|---|
| `ADMIN` | 当前公司全部订单 |
| `COMPANY_ADMIN` | 当前公司全部订单 |
| `DEEP_DEPARTMENT_MANAGER` | 当前部门及所有下级部门 |
| `DEPARTMENT_MANAGER` | 当前部门 |
| `EMPLOYEE` | 本人 |
| `DEPARTMENT_TREE` | 现有订单权限定义的父级、当前及下级部门范围 |

### 7.2 跨部门角色

配置了跨部门管理的角色，沿用现有 `OrderAccessDataRangeAttribute` 语义：

- 包含模式：仅允许配置的部门。
- 排除模式：允许配置部门之外的授权范围。
- 员工选择器只有在用户同时具备员工管理权限时，才展示对应部门员工。
- 用户本人始终可在员工模式查看本人授权订单。

### 7.3 历史部门优先

管理者权限先按订单历史 `contextInfo.departmentId` 判断。仅当订单历史部门为空时，才沿用现有订单权限的兼容逻辑，回退到订单 owner 当前部门。

因此员工调岗后：

- 管理者只能看到该员工在其授权部门产生的历史订单。
- 不会因为员工当前归属变化而获得权限范围外订单。

### 7.4 选择器与查询双重校验

- 选择器只返回当前用户可选的员工和部门。
- 查询接口必须再次校验提交的 ID。
- 伪造员工 ID、部门 ID、“未归属”或网站 ID 必须被拒绝或被安全裁剪，不能越权。
- 历史员工、历史部门、历史域名候选接口也必须应用相同数据权限，不能通过候选接口泄露名称。

### 7.5 网站上下文

- 总后台：统计权限范围内所有网站订单。
- 网站后台：后端强制增加 `contextInfo.websiteId = WebsiteContext.currentWebsiteId`。
- 异步任务不能依赖请求线程的 ThreadLocal；提交任务时必须显式捕获 `companyId`、网站后台标识、`websiteId`、用户数据权限和 `viewMode`。

## 8. 汇率与币种

### 8.1 基准模型

统一使用 USD 基准汇率：

```text
1 USD = X 目标货币
```

订单源币金额换算为目标币金额：

```text
目标金额 = 订单原币金额 ÷ 源币汇率 × 目标币汇率
```

订单币种与目标币种相同时，直接使用原金额，不需要汇率。

### 8.2 汇率优先级

源币汇率：

1. 本次查询临时汇率。
2. 当前用户长期保存的个人汇率。
3. 订单创建时保存的 `contextInfo.currencyExchangeRate`。

目标币汇率：

1. 本次查询临时汇率。
2. 当前用户长期保存的个人汇率。
3. 公司当前有效系统币种 `Currency.exchangeRate`。

USD 汇率固定为 `1`，不可修改。

### 8.3 缺失汇率

当无法得到有效源币汇率或目标币汇率时：

- 订单仍计入订单数、有效/无效订单数和签收率。
- 订单不计入任何目标币种销售额。
- 原币金额仍进入原币汇总。
- 页面提示缺失汇率的币种、订单数和原币金额。
- 禁止默认按 1:1 计算。

目标币种“总销售额”只表示成功换算订单的金额，并显示“另有 N 单缺少汇率，未计入金额”。

### 8.4 个人长期配置

个人报表配置按 `companyId + userId` 隔离，跨设备同步。每名用户只能读写自己的配置，管理员也不能代他人修改。

保存内容：

- 默认目标币种。
- IANA 时区。
- 各 ISO-4217 币种代码的个人汇率。

规则：

- 汇率按币种代码保存，不按数据库币种 ID 保存。
- 同一公司内有效币种代码必须唯一。
- 汇率必须大于 0。
- 最多 8 位小数。
- 最大值为 `1,000,000,000`。
- USD 固定为 1。
- 保存前前端展示换算示例。
- 只保留当前值和更新时间，不保留历史版本。

目标币种只能选择公司当前有效币种，USD 始终可选。币种停用后，已有个人配置保留，但不可继续选为目标币种；如果保存的默认目标币种已停用，页面回退 USD。

统计页面提供“汇率设置”弹窗；个人中心 `/setting/personalCenter` 增加“报表汇率”配置入口，两处使用同一后端配置。

### 8.5 临时配置

- 查询页允许临时覆盖源币和目标币汇率。
- 临时汇率只进入当前查询请求和结果快照，不写数据库。
- 页面刷新或离开后恢复个人长期汇率。
- 临时汇率不写入会话筛选缓存。
- 目标币种临时切换在当前会话保留；只有用户点击“保存为默认”才更新长期配置。

### 8.6 金额精度

- 后端使用 `BigDecimal`。
- 接口金额字段一律返回十进制字符串，禁止返回 JSON 浮点数。
- 前端使用十进制高精度库，禁止用 JavaScript `number` 计算金额。
- 每笔订单以高精度换算，汇总后按目标币种 `fractionDigits` 四舍五入。
- Excel 同时提供高精度金额值和按目标币种格式化的显示金额。

## 9. 页面与交互

### 9.1 菜单

首页菜单结构：

```text
首页
├─ 首页
├─ 统计分析
└─ 斗篷风控
```

统计路由：

```text
/statistics
```

### 9.2 首次进入

- 不自动查询。
- 先加载个人配置、授权范围和默认条件。
- 用户点击“查询”后执行。
- 页面显示统计生成时间和数据截止时间。
- 不自动轮询。
- 提供手动刷新，手动刷新绕过 1 分钟查询缓存。

### 9.3 筛选区

筛选区至少包含：

- 时间范围。
- 时间粒度：按天 / 按月。
- 统计模式：按员工 / 按部门。
- 员工多选或部门树多选。
- 包含历史员工 / 包含历史部门。
- 平台多选。
- 域名远程搜索多选。
- 目标币种。
- 临时汇率。
- 查询、刷新、重置、导出。

员工角色不展示统计模式切换和部门选择。

### 9.4 汇总卡片

顶部展示 8 个指标：

1. 订单数。
2. 有效订单数。
3. 无效订单数。
4. 签收率。
5. 总销售额。
6. 无效订单销售额。
7. 未签收订单销售额。
8. 签收销售额。

### 9.5 趋势图

订单趋势图：

- 总订单数。
- 有效订单数。
- 无效订单数。
- 签收订单数。

签收率趋势图：

- 单独使用百分比坐标。

销售额趋势图：

- 总销售额。
- 无效订单销售额。
- 未签收订单销售额。
- 签收销售额。

订单和销售额不使用同一双轴图，避免量纲误导。

分组趋势最多同时展示 10 个员工或部门。超过 10 个时：

- 图表只显示所有选中对象的汇总趋势。
- 全部分组数据仍可在表格和 Excel 查看。

### 9.6 表格

页面提供：

1. 按时间桶汇总表。
2. 员工或部门分组汇总表。
3. 时间桶 × 员工/部门明细表。
4. 原始币种汇总。
5. 缺失汇率说明。

规则：

- 分组数据分页。
- 分组汇总默认按总销售额降序。
- 支持按订单数、有效数、无效数、签收率和各销售额排序。
- 时间桶按时间升序。
- 固定显示合计行，合计基于全部分组，不是当前页。
- 合计必须与顶部汇总卡片一致。

### 9.7 会话状态

- 时间、粒度、模式、员工/部门选择、平台、域名和目标币种保存在 `sessionStorage`。
- 不写入 URL。
- 关闭浏览器会话或重新登录后恢复默认值。
- 个人汇率和时区由后端长期保存。
- 临时汇率不保存。

### 9.8 窄屏

- 筛选区可折叠。
- 卡片在窄屏下单列。
- 图表允许横向滚动。
- 表格固定首列。
- 不单独设计复杂手机端图表交互。

### 11.7 发起统计

```text
POST /order-statistics/query
```

请求示例：

```json
{
  "startDate": "2026-05-01",
  "endDate": "2026-06-24",
  "granularity": "DAY",
  "dimension": "EMPLOYEE",
  "employeeIds": ["1001", "1002"],
  "departmentIds": [],
  "includeUnassigned": false,
  "platforms": ["V7_SHOP", "SHOPLINE"],
  "domains": ["xl.iwaiw.shop"],
  "targetCurrencyCode": "USD",
  "temporaryExchangeRates": {
    "CNY": "7.25000000"
  },
  "forceRefresh": false
}
```

校验规则：

- `granularity` 只允许 `DAY`、`MONTH`。
- `dimension` 只允许 `EMPLOYEE`、`DEPARTMENT`。
- 当前维度必须至少有一个 ID，或合法选择 `includeUnassigned`。
- 非当前维度 ID 列表必须为空。
- ID 使用十进制字符串，避免前端整数精度问题。
- 平台必须属于 `WebsiteTypeEnum`。
- 域名规范化后精确匹配。
- 临时汇率使用与个人汇率相同的数值规则。
- 后端重新校验所有权限。

同步完成时返回 HTTP 200：

```json
{
  "state": "COMPLETED",
  "resultToken": "opaque-token",
  "snapshotExpiresAt": "2026-06-24T12:30:00Z",
  "result": {}
}
```

5 秒内未完成时返回 HTTP 202：

```json
{
  "state": "PROCESSING",
  "queryJobId": "opaque-job-id"
}
```

- 聚合趋势。
- 原币汇总。

## 13. 查询执行与快照

### 13.1 查询流程

```text
校验请求
  → 捕获公司/用户/网站/权限上下文
  → 规范化筛选与汇率
  → 检查 1 分钟查询缓存
  → 生成用户时区时间桶
  → 执行权限内聚合查询
  → 高精度汇率换算
  → 补齐零数据桶
  → 构建不可变结果
  → 写入 Redis 快照（30 分钟）
  → 返回 resultToken
```

### 13.2 数据库聚合

实现应使用专用原生聚合查询，不加载完整订单实体。

必须满足：

- 显式增加 `company_id` 和 `status <> 'DELETED'`。
- 显式增加网站后台 `website_id` 限制。
- 显式应用订单数据权限。
- 使用 `contextInfo.salesUid` 或 `contextInfo.departmentId` 分组。
- 按订单当前 `order_status` 分类。
- 按订单 `order_time` 过滤。
- 平台、域名按请求过滤。

为正确处理夏令时，应用层生成各时间桶转换后的北京时区边界；SQL 通过边界派生表或等价的范围连接按桶聚合，不依赖数据库固定时差。

汇率换算可在 SQL 和 Java 之间分层完成，但最终必须使用 `BigDecimal`，并保留每个汇率来源及缺失原因。

### 13.3 Redis 键

建议键空间：

```text
order-statistics:result:{companyId}:{userId}:{resultToken}
order-statistics:query-job:{companyId}:{userId}:{queryJobId}
order-statistics:active-query:{companyId}:{userId}
order-statistics:cache:{companyId}:{userId}:{fingerprint}
```

规则：

- 结果快照固定保留 30 分钟，不因分页读取延长。
- 查询缓存保留 1 分钟。
- 缓存指纹必须包含权限签名、网站范围、全部筛选、时区、目标币种和生效汇率。
- 手动刷新设置 `forceRefresh=true`，绕过查询缓存。
- `resultToken`、`queryJobId` 必须不可猜测，并绑定当前公司和用户。

### 13.4 快照一致性

一次查询的：

- 汇总。
- 图表。
- 分页表格。
- Excel。

必须基于同一不可变结果快照。订单状态变化只在用户再次查询或刷新后体现。

### 13.5 Redis 故障降级

Redis 不可用时：

- 允许同步查询直接返回汇总、趋势和最多前 100 个分组。
- 返回 `degraded=true`。
- 禁用快照分页和 Excel 导出。
- 明确提示用户当前处于降级模式。

## 14. 长查询、并发与取消

### 14.1 查询

- 发起查询后，服务端最多等待 5 秒。
- 5 秒内完成则同步返回。
- 超过 5 秒时，同一执行继续在后台运行并返回 `queryJobId`，不能重复执行同一查询。
- 查询任务状态只保存在 Redis，不写数据库。
- 新查询开始时取消该用户旧的未完成查询任务。
- 查询实现必须在主要阶段检查取消标记；可取消 JDBC Statement 时应调用取消，无法立即中止时必须丢弃已取消任务的最终结果。

### 14.2 导出

- 每名用户同时最多一个未完成的统计导出任务。
- 重复提交时返回现有任务 ID 或提示先等待/取消。
- 支持通过现有 `/tasks/cancel/{taskId}` 取消。
- 导出工作线程开始时读取并固定结果快照；开始前快照已过期则任务失败。

## 15. Excel 导出

Excel 只导出聚合结果，不包含逐笔订单。

工作表：

1. `查询说明`
2. `汇总`
3. `时间趋势`
4. `分组汇总`
5. `时间分组明细`
6. `原币汇总`
7. `汇率说明`
8. `缺失汇率`

`查询说明`包含查询条件、统计生成时间、数据截止时间、时区和网站范围。

`汇率说明`包含：

- 临时汇率。
- 个人汇率。
- 公司目标币汇率。
- 使用订单历史汇率时，按币种代码和实际历史汇率汇总订单数。

不导出手机号、密码或其他无关个人敏感信息。

导出文件：

- 使用现有 S3 存储和任务下载接口。
- 保留 24 小时。
- 24 小时后下载返回文件已过期，需要重新导出。
- 使用 S3 生命周期规则或定时清理保证物理文件过期。

## 16. 缓存与当前状态语义

普通重复查询可命中最长 1 分钟的缓存，因此结果表示该缓存生成时刻的订单当前状态。

用户需要立即读取最新状态时点击“刷新”，绕过缓存并重新生成快照。

页面必须展示：

- `generatedAt`。
- `dataCutoffAt`。
- 是否命中缓存。

## 17. 数据库索引

至少评估并新增以下联合索引：

```text
t_orders(company_id, order_time, order_status)
t_order_context_infos(company_id, sales_uid, department_id)
```

同时根据最终 SQL 的 `EXPLAIN` 评估：

```text
t_orders(company_id, platform, order_time)
t_order_context_infos(company_id, website_id, website_url)
```

索引最终顺序以真实查询计划为准，但验收时不能出现大时间范围、多选条件下对订单主表的无约束全表扫描。

## 18. 审计与安全

不保存服务端查询历史，不保存完整统计结果到数据库。

只记录最小结构化审计事件：

- 事件类型：查询或导出。
- 操作者。
- 公司。
- 时间。
- 网站范围。
- 条件摘要。
- 成功、失败或取消。

不得记录：

- 完整统计结果。
- 个人或临时汇率具体值。
- Excel 文件内容。
- 手机号。

所有结果令牌、查询任务和导出任务必须校验当前用户归属。

## 19. 错误处理

| 场景 | 处理 |
|---|---|
| 未选择员工/部门 | 阻止查询并提示选择范围 |
| 员工伪造其他员工 ID | 后端拒绝 |
| 提交权限外部门 | 后端拒绝 |
| 非管理员选择未归属 | 后端拒绝 |
| 按天超过 62 天 | 提示改用按月 |
| 按月超过 5 年 | 阻止查询 |
| 结束日期在未来 | 阻止查询 |
| 非法 IANA 时区 | 拒绝保存配置 |
| 汇率小于等于 0、超过 8 位小数或超过上限 | 拒绝保存或查询 |
| 缺少汇率 | 订单指标正常统计，销售额排除并提示 |
| 快照过期 | 提示重新查询 |
| 查询被新查询取消 | 旧任务状态返回 `CANCELLED` |
| 重复导出 | 返回活动任务或提示取消后重试 |
| Redis 不可用 | 降级返回有限同步结果，禁用分页和导出 |
| 导出文件超过 24 小时 | 提示文件已过期 |

## 20. 测试与验收

### 20.1 统计口径

1. `INVALID` 只进入无效订单数和无效销售额。
2. `DELIVERED` 进入有效订单、签收订单和签收销售额。
3. 其他状态进入有效订单、未签收订单和未签收销售额。
4. 四类销售额满足总额恒等式。
5. 有效订单为 0 时签收率为 `null`。
6. `status=DELETED` 的订单完全排除。
7. PaymentStatus 不影响结果。

### 20.2 维度

1. 员工多选汇总等于各员工分组合计。
2. 部门选择只统计明确部门，不隐式递归。
3. 父子部门同时选择时订单不重复。
4. 员工调岗后按历史 `salesUid` 和历史部门权限统计。
5. 历史员工、历史部门名称可回退订单快照。
6. 未归属只对管理员和公司管理员开放。

### 20.3 权限

1. 管理员和公司管理员可查看当前公司全部范围。
2. 深度部门管理员可访问当前部门和下级部门。
3. 部门管理员只能访问当前部门。
4. 员工只能查看本人。
5. `DEPARTMENT_TREE` 和跨部门角色与现有订单权限一致。
6. 伪造 ID、域名候选、历史候选都不能泄露权限外数据。
7. 网站后台始终限制当前 `websiteId`。

### 20.4 时间

1. 北京时间历史订单可正确换算到用户时区。
2. 夏令时切换日按用户自然日正确分桶。
3. 月份首尾部分区间标记 `partial=true`。
4. 零数据桶完整补齐。
5. 当前日/月数据截止查询时刻。
6. 62 天和 5 年边界校验正确。

### 20.5 汇率

1. 临时汇率覆盖个人汇率。
2. 个人汇率覆盖订单历史源币汇率。
3. 目标币回退公司当前汇率。
4. 同币种不需要汇率。
5. 缺失汇率订单仍计入订单指标。
6. 金额使用字符串返回，前后端无二进制浮点误差。
7. 停用目标币不能新选，旧配置保留并回退 USD。

### 20.6 快照和任务

1. 汇总、图表、分页和 Excel 使用同一快照。
2. 订单状态变化在刷新前不改变旧快照。
3. 快照 30 分钟后失效。
4. 查询 5 秒后正确转异步且不重复执行。
5. 新查询取消旧查询。
6. 每名用户只允许一个活动导出。
7. 查询和导出可取消。
8. 手动刷新绕过 1 分钟缓存。
9. Redis 故障进入明确降级模式。

### 20.7 前端

1. 首次进入不自动查询。
2. 员工角色不显示部门模式。
3. 多于 10 组时图表只显示汇总。
4. 表格分页合计仍基于全部数据。
5. 条件只在当前浏览器会话保留，不写 URL。
6. 窄屏下筛选、卡片、图表和表格可用。

### 20.8 导出

1. Excel 不包含逐笔订单。
2. 各工作表数据与页面快照一致。
3. Excel 包含实际汇率来源、原币和缺失汇率说明。
4. 不包含手机号等敏感字段。
5. 文件 24 小时后不可下载。

## 22. 最终决策摘要

1. V1 只做订单统计，不做商品数量、AI 积分、同比环比和逐单明细。
2. 订单状态口径只依赖当前 `OrderStatus`。
3. 有效订单是非 `INVALID` 订单。
4. 签收率按订单数量计算。
5. 部门统计不隐式递归，权限范围可以递归。
6. 平台和历史域名只作为筛选条件，不作为分组维度。
7. 销售额使用 `totalAmount`，按 USD 基准模型换算。
