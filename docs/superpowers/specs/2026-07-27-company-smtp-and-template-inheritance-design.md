# 公司统一 SMTP 与订单创建模板继承设计

## 目标

邮件发送配置拆分为两个独立维度：

1. 邮件发送配置来源由公司发送模式和部门三态决定。
2. 订单创建模板始终按组织层级与语言独立解析。

本次只改造现有订单创建邮件，不新增其他邮件类型、发送记录或重试机制。

## 发送方式

每一级邮件配置通过 `email.provider` 选择发送方式，未配置时兼容为 `SMTP`：

- `SMTP`：使用主机、端口、用户名、密码、发件人和 TLS 配置发送。
- `AMAZON_SES`：使用 AWS SES v2 API，通过区域、Access Key ID、Secret Access Key、已验证发件人发送；可选 Configuration Set。

Amazon SES 与 SMTP 共用公司/部门继承、测试签名和订单模板解析规则。当前默认区域为 `eu-central-1`。AWS SDK 的默认重试明确关闭，应用也不进行额外重试。

SES 发件邮箱或域名必须在所选区域完成验证；账户处于沙盒时，普通测试收件人也必须完成验证。

## SMTP 模式

公司配置 `email.smtp-mode`：

- `DEPARTMENT_INHERITANCE`：部门按当前部门、最近上级、公司逐级继承 SMTP。
- `COMPANY_UNIFIED`：所有未禁用部门强制使用公司 SMTP。

部门配置 `email.state`：

- `INHERIT`：继承最近上级，最终继承公司。
- `ENABLED`：启用当前部门 SMTP。
- `DISABLED`：明确禁止当前部门发送邮件，不再回退。

统一模式只改变 SMTP 来源，不覆盖部门的有效禁用状态。

旧配置兼容规则：

- 已有部门 `open=true` 等价于 `ENABLED`。
- 已有部门 `open=false` 等价于 `DISABLED`。
- 没有部门配置记录等价于 `INHERIT`。

## 模板解析

订单创建模板与 SMTP 独立解析。每一级组织先匹配订单语言，再匹配该级默认模板：

1. 当前部门当前语言
2. 当前部门默认模板
3. 最近上级部门当前语言
4. 最近上级部门默认模板
5. 继续逐级向上
6. 公司当前语言
7. 公司默认模板
8. 代码内置模板

空主题或空正文不视为有效模板。

## 公司统一 SMTP 启用约束

- 只有公司管理员可以保存公司级邮件配置。
- 公司邮件必须开启，SMTP 主机、端口、用户名、密码和发件人必须完整。
- 管理员必须向指定收件人实际发送固定内容的测试邮件。
- 测试成功后返回与 SMTP 关键字段绑定的签名；配置变更会使签名失效。
- 从部门继承模式切换到统一模式时，管理端二次确认。
- 统一模式运行失败时不回退部门 SMTP、不重试。

## 管理端

- 公司页面显示 SMTP 模式、常驻影响提示、测试收件人与测试按钮。
- 部门页面显示三态状态。
- 统一模式下部门 SMTP 字段只读，但状态和订单创建模板保留。
- 部门为 `DISABLED` 时 SMTP 与模板不可编辑。
- 远程邮件 schema 在客户端做本地增强，并隐藏本次未实现的审单和物流模板。

## 可观测性

不新增发送记录表。结构化日志仅包含订单、公司、部门、SMTP 来源、模板来源、发送结果和脱敏邮箱；不记录 SMTP 密码或正文。
