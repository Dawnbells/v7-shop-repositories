## 与契约的出入 / 说明
- `resolve` 的顶级域名：`DomainUtils` 只接受 `HttpServletRequest`，因此在服务内按同一规则（取 host 最后两段，至少三段）实现；
  `install-url` 仍用 `DomainUtils.getOriginTopLevelDomain(request)`。
- 回调中票据 handle 与 shop 不一致、STORE 票据已含 pendingToken（重放）记为 `INVALID_STATE`；
  ADMIN 成功路径中的非预期异常也回 `INVALID_STATE`（错误码集合内无通用码）。
- STORE 票据失败：校验类失败 → `landing.html?status=invalid`；`TOKEN_EXCHANGE_FAILED`/`APP_NOT_CONFIGURED` → `status=error&code=...`（落地页两者都显示「重新打开」类文案）。
- webhook 注册使用 `uri` 字段（2025-04 起替代 `callbackUrl`，api-version 默认 2026-07），值为 `{app-host}/shopify-app/webhooks`。
- `EditShopifyWebsiteRequest.handle` 也去掉了 `@NotBlank`（前端编辑公开应用记录时可能不传 handle），凭证模式仍由控制器校验。
- `bind` 失败（占用）时保留票据，便于换正确租户登录后重试；成功才删除。

## 风险
- 后台请求开启 OSIV，会话在租户拦截器之后打开并带租户过滤，`findByShopDomain` 的 silent 在后台请求内无法跨租户；
  跨租户占用在 `install-url`/`bind` 里由写库唯一键冲突（`DataIntegrityViolationException` → `HANDLE_TAKEN`）兜底；公开端点（根租户会话）可正常识别。
- 已软删除（status=DELETED）的同 handle 记录仍占用唯一索引，重新安装会得到 `HANDLE_TAKEN`（存量行为，未处理）。
