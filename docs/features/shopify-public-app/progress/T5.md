## 遇到的问题
1. **`ticket` 查询参数与 SSO 票据登录冲突（已解决：主代理决定采用方案 A，前端 query 参数改名为 `bindTicket`）**：`src/router/permissions.ts` 的全局 `beforeEach` 首先调用 `useUserStore().refreshTokenByTicket()`，它用 `src/utils/queryParams.ts#getTicketParams` 从整个 URL（含 hash 部分）读取 `ticket`，存在就调 `loginByTicket(ticket)`，失败则 `resetAll()`（登出），随后 `reloadNoTicket()` 去掉 `ticket` 重载页面。因此后端 `/shopify-app/landing/resolve` 返回的 `https://{host}/#/shopify-bind?ticket={nonce}` 会被当成 SSO 票据：用户被登出、`ticket` 被剥掉，ShopifyBind 拿不到票据。修复需要改本任务文件范围之外的代码，可选方案：
   - A（推荐）：把绑定参数改名，如 `bindTicket`（改 T2 的 `resolve` 返回地址与 `landing.html`，T5 的 `ShopifyBind.vue` 读取处一行）。
   - B：在 `getTicketParams` 中对 hash 路由 `/shopify-bind` 跳过（改 `src/utils/queryParams.ts`）。
   结论：采用方案 A。`ShopifyBind.vue` 已改为读取 `bindTicket`；T2 的 `resolve` 返回地址需为 `https://{host}/#/shopify-bind?bindTicket={nonce}`，`landing.html` 同步。
2. `pnpm lint:eslint` 在基线即报错无法运行：lockfile 锁定 `@element-plus/eslint-config@2.14.3`（peer `eslint ^9`，内部 import `eslint/config`），而项目是 `eslint@8.57.1` + `.eslintrc.js`。属既有工具链问题，不在本任务范围。
3. 现有后端 `EditShopifyWebsiteRequest.clientId` 带 `@NotBlank`；编辑 `PUBLIC_APP` 记录时前端提交整条记录（含 `handle`、`clientId` 原值），若公开应用记录 `clientId` 为空，需 T2 在 `doEdit` 放宽校验。
