## 与契约的出入
- 脱敏语句用**原生 SQL**而非 JPQL：实测 JPQL 会自动带 `status <> 'DELETED'`（实体 `@SQLRestriction`），软删除订单的个人信息
  会漏脱敏。原生 SQL 不走租户过滤，按店铺/客户语句显式带 `company_id`；仓库方法 platform 参数为 `String`（传 `SHOPIFY`）。
- 事件表没有 note 列：「店铺已暂停」「店铺不存在」写入事件的 `error` 列（成功时该列即备注，覆盖之前的失败信息）。
- email 匹配忽略大小写（`LOWER(email) = 小写参数`）。
- 风险记录清空 remote_ip、real_ip 及两者的归属地信息（`*_ip_info`）。
- 缺 `X-Shopify-Webhook-Id` 时用 `sha256(topic + "\n" + 正文)` 作为去重键；落库异常返回 500 让 Shopify 重投。
- 合规记录重试复用：同一事件（topic + shopDomain + receivedAt）上次留下的 PENDING（data_request 还含 MANUAL）记录会被复用，不重复建。
