# 旧版域名配置与证书清理

适用范围：Java 管理端生成的 `/www/nginx/{server}/{domain}.conf` 与
`/www/certs/{company}/{domain}/`。新版 `nginx-front` agent 的 release 不受此改动影响。

## 代码中的保护

- 手动删除和每日孤立资源清理共用 `DomainResourceCleaner`。
- 孤立清理获得工作区锁后重新查询有效域名，不使用巡检开始时的数据库快照。
- 扫描磁盘配置，覆盖服务器删除或改名后的历史目录。删除生成配置后再次检查所有文件的
  `ssl_certificate`、`ssl_certificate_key`、`ssl_trusted_certificate` 引用；仍有引用就保留证书。
- 不自动删除自定义片段。遇到符号链接、无法读取的文件或无法静态判断的证书路径时停止清理。
- 全部配置删除后才删除证书，整批只推送一次。失败时先恢复证书再恢复配置，并保留私钥权限。
- 子域名随顶级域名删除时只修改数据库，不提前推送。
- 写配置前检查证书对是否存在；所有 Java 推送入口在锁内检查证书文件存在、可读且非空，
  同步等待脚本结束，非零退出码作为失败。此检查不能替代前端机上的 `nginx -t`。

## 部署要求和未验证边界

1. 多实例必须共享同一个证书工作区及支持文件锁的文件系统。默认锁文件为
   `/www/certs/.nginx-workspace.lock`，同一 JVM 内还使用可重入锁；事务中的锁保留到事务结束。
   可以用 JVM 参数 `-Dv7.nginx.workspaceLock=...` 指向同一共享卷上的稳定路径。
   锁文件必须排除在配置 Git 仓库之外，且不能被清理、替换或随 checkout 重建。
2. 所有写同一工作区的管理端实例应同时升级。旧实例或人工脚本不遵守此锁，不能与清理并发执行。
3. `/scripts/push.sh` 和旧前端机拉取/重载脚本不在本仓库。本次测试不代表已验证生产部署脚本。
   推送脚本必须同步完成实际发布，并正确传递失败退出码；不能后台启动发布后立即退出。
4. 前端机应先在候选目录执行 `nginx -t`，通过后才切换完整的配置和证书并 graceful reload。
   禁止先停止 Nginx 再尝试加载候选配置；应保留旧版本用于失败恢复。
5. 数据库事务、Git 推送和前端应用不是一个分布式事务。推送异常可能表示远端已接受提交但响应丢失；
   本地文件恢复不等于远端回滚。出现此情况应核对远端提交和前端当前版本，再发布完整快照。
   仓库内缺少实际 Git 工作区位置和部署脚本，因此没有自动执行远端回滚。

## 验证

相关回归测试覆盖历史服务器、多服务器统一发布、残留引用、配置/证书删除失败、推送失败恢复、
新建域名保护、清理与写入互斥、事务完成前的锁持有，以及缺证书时拒绝写配置和启动推送脚本。

生产验收还应在测试前端机验证：坏候选配置不切换、重载失败旧进程仍服务，以及完整版本回滚。
